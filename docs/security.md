# Security and responsible AI

## Trust boundaries

The main boundaries are:

1. browser to web tier;
2. web managed identity to Hosted Agent;
3. Hosted Agent identity to Azure AI Search;
4. ingestion operator to Storage, embeddings, and Search;
5. CI/CD principal to Azure control and data planes.

Each identity has a different role and should remain separate.

## End-user authentication

The repository authenticates **service to service** with managed identity. It does
not provision an Entra application for human sign-in because tenant app-registration,
groups, Conditional Access, and consent are organization-specific.

For enterprise use, place the private web endpoint behind an approved identity-aware
ingress and enforce:

- Entra sign-in and tenant restriction;
- Conditional Access and MFA;
- authorization by group/application role;
- TLS 1.2+ with an approved certificate;
- session timeout, CSRF protection where cookies are used, and rate limits.

Do not put the development-mode public HTTP URL on the internet with enterprise data.

## Prompt injection and retrieval safety

Retrieved documents are untrusted. The system prompt explicitly tells the model to
treat passages as evidence rather than instructions. Additional production controls:

- ingest only approved sources;
- malware-scan uploaded files before extraction;
- strip active content and macros;
- retain source ownership/classification metadata;
- evaluate indirect prompt injection samples;
- filter documents by the caller's authorization when sources have different ACLs;
- never index credentials, tokens, or regulated data without an approved design.

The sample index is shared across all users. If document-level permissions differ,
add an `allowed_principals` field and a mandatory Search filter generated by trusted
server-side code. Never let the model create or remove that authorization filter.

## Logging and privacy

Prompt and response content capture is disabled by default with
`OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT=false`.

Still review:

- application logs and exception messages;
- Foundry traces and evaluations;
- Cosmos conversation content;
- Search query telemetry;
- Application Insights sampling and workspace access.

Set retention and data-access roles from policy. Treat conversations and traces as
customer content that may contain personal data.

## Keyless authentication

- Storage shared-key authentication is disabled.
- Cosmos local authentication is disabled.
- Search local authentication is disabled.
- ACR admin credentials are disabled.
- Applications request Entra tokens at runtime.
- The repository contains no application API keys.

The Application Insights connection string contains an ingestion identifier and is
kept in protected Terraform state/runtime environment. It is not a general Azure
management credential.

## RBAC review

Run after deployment:

```bash
az role assignment list \
  --scope "$(terraform -chdir=infra/terraform output -raw foundry_project_id)" \
  --all --output table
```

Also inspect assignments on ACR, Search, Storage, and Cosmos. Remove broad temporary
roles used during initial setup.

## Network review

Private mode should show:

- public access disabled for Foundry, Search, Cosmos, Storage, and ACR;
- private DNS resolving to the PE subnet;
- a dedicated `/24` Foundry agent subnet;
- NSGs associated to the Foundry and ACI subnets;
- no overlapping VNet/peering ranges;
- approved egress only;
- no TLS inspection on Foundry/Entra control traffic.

The Hosted Agent VNet injection must be present when the Foundry account is first
created. It cannot currently be retrofitted to an existing Hosted Agent account.

The current Hosted Agent preview can keep the agent's Responses endpoint publicly
addressable even when the Foundry account and its dependencies use private
networking. Entra authorization is still required, but organizations that require a
private-only application ingress should expose the web tier through an approved
private gateway and treat the agent endpoint as a documented platform exception.

This reference sends telemetry to the standard Azure Monitor ingestion endpoints.
If policy requires private telemetry paths, add Azure Monitor Private Link Scope
(AMPLS), private endpoints, and the corresponding private DNS zones before
production.

## Model and output safety

Before production:

- configure and test the appropriate Foundry content-safety policy;
- create golden question/evidence/answer evaluation sets;
- measure groundedness, citation correctness, relevance, refusal quality, latency,
  and cost;
- test data exfiltration, system prompt requests, encoded attacks, tool misuse, and
  oversized inputs;
- add human review for high-impact decisions;
- display the user warning and an escalation path.

This agent should support decisions, not silently make employment, safety, legal,
financial, or access-control decisions.

## Supply chain

- Pin production Python dependencies with hashes using an approved dependency
  management process.
- Scan containers and generate an SBOM.
- Enable Defender for Cloud/ACR image scanning where licensed.
- Sign images and enforce trusted registries.
- Use immutable tags/digests and protected deployment environments.
- Run the Hosted Agent from a reviewed commit and retain the agent-version-to-commit
  mapping.
